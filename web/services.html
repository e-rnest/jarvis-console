Jarvis Console

Lightweight, read-oriented front door for household services. It is an orchestrator/client only: every downstream service continues to operate if Console is unavailable.

Deployment

  • Python 3.12 standard-library HTTP server with static HTML, CSS, and vanilla JavaScript.
  • Compose project, service, container, and hostname are jarvis-console; restart policy is unless-stopped.
  • Publishes 192.168.1.100:8791 to container port 8080 by default and joins the external jarvis-receipt-services network.
  • Container health checks GET /health. JSON logs rotate at 5 MiB with three retained files.

Contracts

  • GET /health reports Console process health only.
  • GET /api/status checks supported services concurrently with bounded per-service timeouts and isolates every result.
  • POST /api/actions/morning-brief dispatches exactly one Receipt request with no automatic retry and a process-local in-flight guard.
  • GET /services serves this catalog.

Console status terms are deliberate: healthy means an accepted contract succeeded; failed means a supported contract explicitly reported failure; unknown means truth could not be established; unavailable means no accepted health contract exists.

Receipt Service

Owns thermal receipt printing and the Morning Brief scheduler. Console never reproduces its scheduler or print logic.

Deployment and dependencies

  • Container receipt-service, restart unless-stopped, published on 192.168.1.100:8788, with a 90-second stop grace period.
  • Joins its default network and the external jarvis-receipt-services network, where it has receipt-service and legacy morning-brief aliases.
  • Uses a named persistent schedule-state volume so a claimed daily run survives container replacement.
  • Prints raw ESC/POS over TCP to the receipt printer on port 9100. The configured printer is not probed by health.
  • Morning Brief gathers its own weather, market, headline, daily-content, and trivia inputs; upstream failures are handled within Receipt rather than by Console.

Current HTTP surface

  • GET /health — service, scheduler configuration/state, and print-lock state.
  • POST /print/morning — deliberate Morning Brief physical print.
  • POST /print/inventory — inventory receipt.
  • POST /print/jeopardy and optional ?id=… — Jeopardy clue receipt.
  • POST /print/capabilities — printer capability test output.
  • POST /print/image — PNG/JPEG multipart image print with bounded upload and rendering limits.

Important behavior

  • The daily scheduler uses a durable at-most-once claim. Automatic print retries are intentionally absent.
  • Manual prints do not consume the scheduler's daily claim.
  • A shared nonblocking print lock prevents concurrent physical jobs.
  • An HTTP success means the service completed its accepted send path; the printer protocol cannot prove that paper physically emerged.
  • Health does not prove printer reachability or the availability of content providers.

Label Service

Owns Brother label rendering/printing, reusable quick labels, and lightweight refrigerator/freezer inventory workflows.

Deployment

  • Flask service published on host port 5050, restart unless-stopped.
  • The Compose deployment bind-mounts the project at /app; there is no container-level Compose healthcheck.
  • Prints to a Brother QL-710W-compatible raw TCP endpoint on port 9100 using brother_ql, with a 62 mm / 696-pixel rendering model.

Browser and data features

  • /print — main print interface.
  • /labels — add, rename, delete, reorder, and print reusable quick labels.
  • /inventory and /inventory/frozen — fridge and freezer inventory, including edit, archive, freeze, and restore flows.
  • Inventory uses soft states for active, frozen, and archived items. Freezing preserves the original creation time and does not print another label.
  • Supported layouts include timestamps, images, text, timestamped text, one/two-line storage labels, large two-line storage labels, and item labels. Appropriate text routes support regular and bold font weight.
  • A bounded rotating JSONL audit records print attempts locally; it is operational data, not a Console feed.

Important behavior

  • GET /health proves the HTTP process responds; it does not prove the printer is reachable.
  • Only the item-print workflow creates inventory rows.
  • Print calls are not automatically retried, and the raw printer protocol does not confirm physical paper output.

Jeopardy Service

Read-only clue browser and API backed by a generated SQLite corpus, with Receipt-owned physical clue printing.

Deployment and data

  • Container and hostname jeopardy-service, restart unless-stopped, default host port 8789.
  • Joins its default network plus jarvis-receipt-services and mounts the generated SQLite corpus read-only.
  • Container health checks GET /health, which validates corpus readability rather than merely serving the homepage.

Features and API

  • Browser UI supports random and daily clues, answer reveal, canonical ?id=… links, category boards, sharing, and printing.
  • GET /api/jeopardy/random, /clues/{id}, /clues/{id}/category, and /daily?date=… are the current read APIs.
  • POST /api/jeopardy/clues/{id}/print delegates one print to Receipt Service.
  • Clue IDs come from the generated corpus and may change if source data is rebuilt.

TriviaROM

Read-only browser and API over an archived multi-pack trivia corpus. Receipt uses its random-question API for Morning Brief content.

Deployment and corpus

  • Compose project, service, container, and hostname are triviarom-service; restart is unless-stopped.
  • Publishes host port 8790, joins its default network and jarvis-receipt-services, and health checks GET /health.
  • The image contains 68 archived dataset files: 145,600 total records and 137,173 playable records. Five primarily non-English packs are excluded from the default playable pool.
  • No persistent runtime state is required. A 256-question recent-history ring is in memory and resets on restart.

Features and API

  • GET /api/trivia/random and ?pack=… select playable questions.
  • GET /api/trivia/packs lists pack metadata; GET /api/trivia/questions/{id} resolves stable 12-hex-character question IDs.
  • All POST routes are rejected. Choice order is deterministic for each question, and direct-ID reads do not alter the recent-history ring.
  • The browser supports pack selection, answer reveal, history-safe canonical ?id=… links, and 2–4 choice questions.

Jellyfin

Household media server. Console currently treats it as launch-only because no accepted unauthenticated health contract has been established.

Known current setup

  • Primary entry point: http://jellyfin.home. A direct port-8096 entry point is also known operationally.
  • The mounted directory contains Jellyfin runtime configuration, cache, metadata, plugins, databases, and logs rather than the deployment's Compose definition.
  • Application HTTP is enabled, built-in HTTPS is disabled, UPnP is disabled, and remote access is enabled. TLS/host routing is therefore an external concern.
  • Live TV is configured with an M3U tuner and an XMLTV guide provider. Source URLs and tokens are deliberately omitted.
  • Console's current TV Guide shortcut opens the Jellyfin Live TV guide directly.

A successful Jellyfin homepage fetch would not be a truthful media-server health contract. Console will continue to say status unavailable until an accepted endpoint and response schema are verified.

BlackTorrent

VPN-isolated qBittorrent downloader. qBittorrent has no independent network interface: it shares Gluetun's network namespace and reaches the LAN only through Gluetun's published WebUI port.

Deployment

  • gluetun uses qmcgaw/gluetun:v3, OpenVPN UDP, NordVPN, firewalling, NET_ADMIN, and /dev/net/tun.
  • qbittorrent uses the LinuxServer image and network_mode: service:gluetun. Both services use restart policy always.
  • Gluetun publishes 192.168.1.100:8080 to qBittorrent's WebUI. qBittorrent itself publishes no ports.
  • qBittorrent is configured to bind its traffic to tun0, disable UPnP and port forwarding, watch an inbox directory, and separate incomplete from complete downloads.
  • Gluetun state, qBittorrent configuration, watch input, and download data are persistent host directories.

Health boundary

  • Console currently performs one unauthenticated GET / against the WebUI and marks 2xx as healthy. This proves only browser reachability through Gluetun's namespace.
  • The stronger operational check is: Gluetun running and healthy, qBittorrent running, tun0 visible inside qBittorrent, and both processes sharing the same network namespace.
  • The reported acceptance checks include a matching Gluetun/torrent leak-test VPN address and successful cold-boot recovery. These are operational observations, not continuously monitored Console facts.
  • Credentials, VPN address, torrent names, and filesystem contents are not exposed in Console or this catalog.

Never restart Gluetun alone from Console. A Gluetun-only restart can leave qBittorrent attached to an obsolete namespace. If a future restart control is approved, it must operate on the complete Compose stack and must not be added as a casual dashboard action.

Scrypted

Camera and home-automation bridge with persistent device/plugin state.

Deployment facts established from Compose

  • Uses ghcr.io/koush/scrypted with restart policy unless-stopped.
  • Uses host networking rather than published Compose ports. Network identity and multicast behavior are therefore coupled to the Docker host.
  • Enables Docker Avahi support and persists server state under the mounted Scrypted volume.
  • The runtime data contains installed plugin/device state, including HomeKit components. That private state was not enumerated into this public household catalog.

The mounted Compose file does not declare a canonical browser URL, explicit healthcheck, or fixed image tag. No Scrypted card or shortcut should be added until its accepted LAN URL and truthful health contract are confirmed from the deployed configuration.

Integration map

  • Console → Receipt, Jeopardy, TriviaROM: backend HTTP over the shared jarvis-receipt-services Docker network.
  • Console → Label: backend HTTP through the accepted LAN route on port 5050.
  • Console → BlackTorrent: backend HTTP to the Gluetun-published qBittorrent WebUI.
  • Console → Jellyfin: browser navigation only; no health request.
  • Receipt → TriviaROM and Jeopardy: content/print integrations over the shared Docker network.
  • Jeopardy → Receipt: clue-print request; Jeopardy does not speak directly to the printer.
  • Receipt → Label: accepted LAN HTTP route for label-related integration.
  • Receipt and Label → printers: each service owns its own raw TCP printer protocol and rendering behavior.
  • BlackTorrent: qBittorrent's only network namespace is Gluetun's; there is no Console/Docker control integration.
  • Jellyfin and Scrypted: operationally independent of the shared Jarvis application network.

Console shortcut candidates

These are navigation ideas, not an instruction to invent APIs or add operational controls. Existing actions are identified separately.

  • Jellyfin — TV Guide: already present; opens /web/#/livetv?collectionType=livetv&tab=1.
  • Label — Quick Labels: safe navigation to http://label.jarvis.home/labels.
  • Label — Fridge: safe navigation to http://label.jarvis.home/inventory.
  • Label — Freezer: safe navigation to http://label.jarvis.home/inventory/frozen.
  • Jellyfin — Admin: optional authenticated navigation to the server dashboard, useful only if day-to-day administration belongs on the appliance panel.
  • Receipt — Print Morning Brief: already present as the sole Console physical action, with confirmation, no retry, and ambiguity handling.
  • Receipt — Inventory receipt or capability test: APIs exist, but these create physical output and should not become casual secondary links. Add only after a specific household workflow and the same safety guardrails are approved.
  • Jeopardy: no fixed secondary link is compelling. Category views require a clue context; random play is already the primary launch experience.
  • TriviaROM: no stable pack-picker deep link currently exists; pack selection already lives in the application.
  • BlackTorrent: no secondary button recommended. Do not add Gluetun-only restart, credential, IP, or Docker controls.
  • Scrypted: defer shortcuts until the canonical URL and supported deep links are verified.

Operating and safety rules

  • Current implementation and physically accepted behavior outrank older inventory prose.
  • Do not infer health from a homepage when a real health endpoint exists.
  • A downstream failure must never take down Console; all checks require bounded timeouts.
  • Browser-facing links use LAN-reachable names or addresses, never internal Docker hostnames.
  • Physical print requests are deliberate, confirmed, and never automatically retried.
  • Console does not own Docker, restart containers, aggregate logs, edit service configuration, or duplicate service business logic.
  • Do not expose secrets, API tokens, password hashes, VPN addresses, media history, camera/device state, torrent contents, or private databases.
  • Floating image tags in BlackTorrent and Scrypted can change behavior on pull. Treat upgrades as explicit maintenance with post-upgrade acceptance checks.
  • Reverse proxy and DNS are external infrastructure; repository changes do not become live until the Console image is rebuilt/recreated through the accepted deployment process.

Known documentation gaps

  • The older root service inventory predates Console, TriviaROM, BlackTorrent, Scrypted, and recent Receipt/Label behavior. This page records the newer source-backed view.
  • Jellyfin's mounted directory does not contain its container/Compose definition, so image tag, restart policy, and exact host-volume wiring are not claimed here.
  • Scrypted's canonical LAN/reverse-proxy URL and an accepted health endpoint were not present in its Compose file.
  • Local DNS and Synology reverse-proxy configuration were not part of the mounted service sources and remain external documentation concerns.
  • BlackTorrent's stronger VPN/namespace health requires authorized runtime Docker inspection; Console intentionally lacks that access today.

When one of these gaps is resolved, update this page from the accepted deployment source—not from assumption or a transient homepage response.
